# content · 内容与运营

> 第三位成员的工作区：**文档协助 + 小红书 Build in Public 运营**。

## 你负责什么

1. **小红书 Build in Public**（对应赛道 07）：把项目从 0 到 1 的过程持续晒在小红书，冲"社区人气奖"。
2. **文档协助**：帮忙润色/维护 `../docs/` 里的方案与对外材料，保证对外口径一致。

## 这个文件夹里有什么

| 文件 | 用途 |
|---|---|
| `小红书发布计划.md` | 3 天 Build in Public 内容日程 + 每篇要点 + 话题标签 + 赛道提交问答草稿 |
| `项目速览-对外文案素材.md` | 写文案直接取用的项目介绍/故事/关键数据/口径红线 |
| `drafts/` | 你的草稿与已发布记录 |

## 先读这些（了解项目）

- `../README.md`：项目总览
- `../docs/无声之声-项目方案.md`：§1 定位、§2 用户（故事都在这）、§8 赛道
- 本文件夹 `项目速览-对外文案素材.md`：帮你把上面的内容浓缩成可直接发布的口径

## ⚠️ 两条红线（务必遵守）

1. **真实用户隐私**：涉及身边真实用户的故事，**必须先获本人同意 + 匿名处理**，不得暴露可识别信息，不消费别人的困境博眼球。
2. **不夸大**：不写成"治疗/治愈失语"、不承诺未经验证的性能；我们是"帮人把话说出口的辅助工具"，不是医疗器械。

## 协作方式

- 内容相关的改动放在本文件夹，随时提交；发布前如涉及对外口径，与团队快速对一下。
- 详细协作规范见 `../docs/接口契约.md` 不适用于内容——你主要在 `content/` 和 `docs/` 里工作，和代码目录不冲突。
