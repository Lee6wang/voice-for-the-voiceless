# 协作推送指南

> 给三位协作者的 Git 使用说明：**谁推什么、怎么推、什么绝不能推**。
> 仓库：`voice-for-the-voiceless`（私有）· main 分支保持可运行。

---

## 0. 一次性准备（每人首次）

```bash
git clone https://github.com/Lee6wang/voice-for-the-voiceless.git
cd voice-for-the-voiceless
npm install                     # 根目录装好 shared/backend/glasses-app
cp .env.example backend/.env    # 填云 API 密钥（这个文件永不提交）
```
- config-app 需单独初始化，见 `config-app/README.md`。

---

## 1. 谁推什么（按目录归属，天然不冲突）

| 你 | 只改这些目录 | 内容 |
|---|---|---|
| **A** | `glasses-app/` | 眼镜插件：HUD、R1 事件、状态机、云编排 |
| **B** | `backend/` + `config-app/` | 云后端接口、云 API 编排；配置 App |
| **C** | `content/`、`docs/`（文案类） | 小红书内容、对外文案、文档润色 |
| 共享 | `shared/`、`docs/接口契约.md` | **改这两处前必须先同步对方**（见 §5） |

> 各自只动自己的目录，冲突概率极低。跨目录改动前先在群里说一声。

---

## 2. 日常推送流程（每次提交都这样）

```bash
git pull --rebase origin main       # ① 先拉最新，减少冲突
# ... 改你负责目录里的代码 ...
git add <你的目录>                   # 例：git add glasses-app
git commit -m "type(scope): 一句话说明"
git push origin main                # 直接推 main（小改动）
```

**大改动 / 跨模块 → 用分支 + PR：**
```bash
git checkout -b feat/glasses-hud
# ...改，commit...
git push origin feat/glasses-hud
# 去 GitHub 开 Pull Request，让队友扫一眼再合并
```

---

## 3. commit message 约定

格式：`type(scope): 说明`
- **type**：`feat`(功能) / `fix`(修) / `docs`(文档) / `chore`(杂项) / `scaffold`(骨架)
- **scope**：`glasses` / `backend` / `config` / `shared` / `content` / `docs`

例子：
```
feat(backend): /candidates 接入 DeepSeek 生成候选
fix(glasses): 修复 swipe 高亮越界
docs(content): 发布 Day1 踩坑笔记
```

---

## 4. 分支策略（3 天从简）

- `main` **始终保持可运行**（别把跑不起来的代码推 main）。
- 小改动：直接推 `main`（目录不重叠，安全）。
- 大改动/没把握：开 `feat/xxx` 分支 → PR → 合并。

---

## 5. ⚠️ 改接口/共享类型的特殊流程（唯一高冲突点）

要改 API 结构、字段、或模板库时：

1. **先改** `shared/src/types.ts`（或 `templates.ts`）+ `docs/接口契约.md`
2. **群里 @ 对方**说清楚改了什么
3. 对方 `git pull` 后再各自改实现

> `shared/` 是"单一真相源"，两端 import 它。类型不一致编译期就会报错——但前提是大家改的是同一份、且同步了。

---

## 6. ⛔ 绝不能推的东西

- **`backend/.env` 和任何密钥 / token / API key**（已 gitignore，仍要肉眼确认）
- `node_modules/`、`dist/`、`.expo/`、构建产物（已 gitignore）
- 大二进制：`*.zip`、`*.wav`、`*.bin`、录音、模型（已 gitignore）

**每次 `git push` 前先 `git status` 扫一眼**，确认没有上面这些。

---

## 7. 常见问题

- **push 被拒（rejected）**：远程有新提交 → `git pull --rebase origin main` 再 `git push`。
- **冲突**：一般只发生在 `docs/接口契约.md` 或 `shared/`；打开文件手动合并冲突段，`git add` 后 `git rebase --continue`。
- **每天开工第一件事**：`git pull --rebase origin main`。
- **不小心 commit 了 .env**：**先别 push**，`git rm --cached backend/.env` 再 commit；已 push 的立刻改密钥。

---

## 8. 提交前自查清单

- [ ] `git status` 里没有 `.env` / `node_modules` / 大文件
- [ ] 只改了自己负责的目录（跨目录/改接口已同步对方）
- [ ] commit message 符合 `type(scope): 说明`
- [ ] 本地能跑（后端起得来 / 眼镜插件能开）
