# 无声之声 · 接口契约与开发规格

> 本文件是**开发时天天看、天天更新的活文档**（区别于对外的项目方案）。
> 目的：把 `glasses-app`（眼镜插件，含手机端配置界面）/ `backend`（薄后端）两方的边界钉死，让两人并行开发在联调时不炸。
> 版本：v0.2（2026-07-23 定案：**单插件架构**——`config-app` 已并入 `glasses-app`，见 §0）

---

## 0. 模块与归属

> **架构定案（v0.2）**：真机验证插件可在手机屏渲染可交互 UI（官方 asr 模板的 companion UI 范式），故**取消独立 `config-app`**，个性化配置并入 `glasses-app` 的手机端页面，配置存 SDK 本地 KVS（`bridge.setLocalStorage/getLocalStorage`），不再经后端中转。

| 模块 | 归属 | 技术栈 | 职责 |
|---|---|---|---|
| `glasses-app` | A | TS + Even Hub SDK | 手机端多页面(配置/功能菜单) + 眼镜 HUD + 采 PCM、输入事件、云编排、播 TTS、状态机；配置存本地 KVS |
| `backend` | B | serverless / 小 Node | 云 API 密钥代理 + 编排（转发 ASR/LLM/TTS，`/candidates` 内做候选生成/语义 agent）；**不再管配置存储** |
| ~~`config-app`~~ | — | — | **已取消**：并入 `glasses-app` 手机端页面 |

> 说明：按 Even Hub 架构，`glasses-app` 是跑在手机上的 Web 插件——**手机屏是它的配置/菜单界面，眼镜是它的 HUD+输入**。云 API（ASR/LLM/TTS）**一律经 `backend` 代理**（密钥不落客户端）；个性化配置则**留在插件端 KVS**，不进后端。
>
> ⚠️ **联网权限**：插件访问后端/云的每个主机必须写进 `app.json` 的 `network` 权限白名单（`evenhub pack` 拒绝空白名单）。dev 期填后端 LAN 地址，上线换 https 域名。

## 1. 数据模型（TypeScript 类型，三方共用）

```ts
// 一条候选回复
interface Candidate {
  id: string;        // 稳定 id，供选择/埋点
  text: string;      // 展示&朗读文本，≤12 字
}

// 一屏候选（固定 4 条）
interface CandidateSet {
  turnId: string;        // 对应哪一轮对方发言
  heardText: string;     // ASR 转写的“对方说了什么”（可显示在 HUD 顶部）
  candidates: Candidate[]; // 长度固定 4
  highlightIndex: number;  // 当前高亮项，默认 0
}

// 输入事件（来自 R1 戒指 / 镜腿触控，Even SDK 原生事件）
// 语义随状态而变，见 §2 状态机
type RawInput =
  | 'tap'           // IDLE: 开始聆听 ; 候选态: 确认选中→朗读
  | 'swipe_up'      // 候选态: 上一个候选
  | 'swipe_down'    // 候选态: 下一个候选
  | 'double_tap'    // IDLE: 唤主动模式 ; 候选态: 换一批
  | 'temple_double_tap'; // 任意状态: 紧急呼救（镜腿独立表面）

// 用户个性化配置
interface UserProfile {
  userId: string;
  name?: string;             // 用于候选里的自我介绍
  commonPhrases: string[];   // 常用语，喂进 LLM prompt
  tone?: 'gentle' | 'plain' | 'humor'; // 语气偏好
  voice?: string;            // TTS 音色 id
  emergencyText?: string;    // 紧急呼救要喊的话
}
```

## 2. glasses-app 主流程与状态机（A 负责）

**触发模型：push-to-listen（按戒指开始听，非常开）**

```
状态机：
IDLE ──tap──→ LISTENING(采音 3~5s) ──→ THINKING(调 /asr /candidates)
                                              │
                                              ↓
 IDLE ←─tap确认后─ SPEAKING(播 TTS,静音麦) ←─ CANDIDATES(HUD 显 4 候选)
                                              │ swipe 导航 / double_tap 换一批
 IDLE ──double_tap─→ 主动模式轮盘 → CANDIDATES
 任意状态 ──temple_double_tap─→ 紧急：直接播 profile.emergencyText
```

- **防回声**：只在 LISTENING 采音；SPEAKING 期间静音麦克风——杜绝“听到自己”的死循环。
- **HUD 分段反馈**：LISTENING显“🎧聆听中…”、THINKING 显“💭思考中…”（候选要 2~4s，不显会像卡死）。
- **确认两步制**（防误触，可选）：候选态首次 tap 选中高亮项，再 tap 才朗读（Day2 视误触率启用）。

## 3. backend HTTP 接口（B 负责，`glasses-app` 调用）

> 全部 POST，JSON。`backend` 内部再去调各家云 API（密钥只在 backend）。

### 3.1 `POST /asr` — 语音转文字
```
请求:  { "audio": "<base64 PCM 16kHz mono>", "final": true }
返回:  { "text": "对方说的话" }
```
- 流式版可选：`/asr/stream`（WebSocket），Day2 有余量再做；Day1 先用整段。

### 3.2 `POST /candidates` — 生成候选（核心）
```
请求:  {
  "turnId": "t_123",
  "heardText": "你中午想吃什么？",
  "profile": { ...UserProfile },
  "exclude": ["面条","米饭"],   // 换一批时传，避免重复
  "context": {                  // 可选：场景上下文（v0.3 新增，shared.SceneContext）
    "localTime": "12:10",       // 本地时间 HH:mm（插件必带）
    "timeOfDay": "午餐时段",     // 时段标签
    "scene": "餐厅",            // 场景标签（插件手选场景映射；缺失时 backend 可按 lat/lon 反查 POI）
    "lat": 30.1, "lon": 120.2   // 可选
  },
  "history": [                  // 可选：多轮上下文（v0.3 新增，shared.ConversationTurn[]，最近≤3轮）
    { "heard": "你吃了吗", "said": "还没呢" }   // A 端已发送；B 端消费为可选增强（不接也不报错）
  ]
}
返回:  {
  "turnId": "t_123",
  "candidates": [ {"id":"c1","text":"面条"}, ... 共4条 ]
}
```
- backend 内部：拼 prompt（注入 name/commonPhrases/tone）→ 调云 LLM → 解析出 4 条 ≤12 字。
- **双层兜底**（关键，两者不同）：
  - ① **backend 侧**：backend 可达但 LLM 超时/报错 → backend 返回模板库候选。
  - ② **插件端（客户端）**：网络/backend 本身不可达（断网）→ glasses-app 用**内置的本地模板库**出候选。⚠️ 断网时 backend 也够不着，所以“无网也能演”的模板库**必须在插件端**，不能只放 backend。
- 模板库内容见方案 §附录 A；两处共用同一份（可从 backend 同步到插件内置）。无论哪层，保证永远返回 4 条。

### 3.3 `POST /tts` — 文字转语音
```
请求:  { "text": "我想吃面条", "voice": "default" }
返回:  { "audio": "<base64 mp3/wav>", "mime": "audio/mpeg" }   // mime 可选，缺省按 mp3；glasses-app 播到手机扬声器
```
- backend 实现：msedge-tts（免密钥）+ 同文本磁盘缓存；失败返空 audio，插件降级 speechSynthesis。

### 3.4 `GET /profile` / `POST /profile` — 可选（插件不依赖）
> 插件端配置存本地 KVS（见 §4），**不调此接口**。backend 保留了 JSON 文件持久化实现（保存时预录 TTS 关键句到磁盘缓存），作为未来跨设备同步的预留能力。

## 4. 手机端配置页（A 负责，已并入 glasses-app）

- 插件手机屏的一个极简表单页：名字、常用语（多行）、语气（三选一）、紧急呼救语、（可选）音色。
- 保存 = `bridge.setLocalStorage('profile', JSON.stringify(UserProfile))`；聆听会话开始时 `getLocalStorage('profile')` 读出。
- **无账户系统**：userId 用固定值即可（单设备本地存储，Demo 够用）。
- 多页面：手机屏可做「菜单页 + 配置页 + 功能选择页」（普通网页视图切换）；眼镜端多布局用 `rebuildPageContainer` 切换。

---

## 5. 契约约定（避免联调翻车）

1. **候选恒为 4 条**、每条 `text ≤ 12 字`；不足由 backend 补兜底句。
2. **turnId** 全程透传，用于把"对方这句话"和"这批候选"对齐，避免串话。
3. 所有云调用**只走 backend**；`glasses-app` 不持有任何密钥。
4. 音频编码统一：PCM 上行 16kHz mono base64；TTS 下行 mp3/wav base64。
5. backend 任何异常都要返回**可渲染的兜底**（4 条通用候选 / 一段兜底 TTS），前端不白屏。
