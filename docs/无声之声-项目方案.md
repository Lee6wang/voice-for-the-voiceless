# 「无声之声」项目方案与可行性评估

> AdventureX 黑客松参赛项目 ｜ 团队：2 人 ｜ 开发时间：3 天
> 文档版本：v1.0（2026-07-22）
> 状态标记：✅ 已证实（有文档/代码依据）｜ 🟡 待验证（有依据但需实测）｜ 🔴 高风险（需预案）

## 1. 一句话定位

> **当你卡壳、不敢开口、或担心发音被误解的那一瞬——想说的话已经浮现在眼前，你只需轻轻选一个，设备替你从容说出口。**

面向「能听、能想、却卡在‘说出口’这一步」的人的**社交表达搭子（“嘴替”）**：设备实时听懂对方说的话，端侧 AI 生成 4 个最可能的回答候选，用户用 Even R1 戒指选择，TTS 代为发声。全程本地。

## 2. 目标用户与痛点

> 用户定位来自团队身边真实接触的人群（已得到本人同意，案例均匿名处理），而非从新闻里看来的抽象群体。

| 人群 | 共同特征 | 现状 |
|---|---|---|
| 社交回避/不敢开口（社恐、选择性缄默） | 能说，但在人前开不了口 | 冷场、逃避对话，错过表达时机 |
| 发音不标准/构音差异 | 一开口就被要求“再说一遍” | 被反复追问，久之干脆沉默 |
| 思维/节奏与大多数人不同（神经多样性候选） | 临场组织语言跟不上对话节奏 | 寒暄/突发提问时卡住 | 

**共同痛点**：他们**能听、能想、有很多想表达**，卡住的只是“把话顺畅说出口”这一步。

**现有方案的缺失**：要么是医疗 AAC “翻图标字典”（面向不能说话的人，与本群体错位）；要么是手机打字（打断对话节奏、社交场合尴尬）。**没有一家做到“听懂对话、预测回答、在你卡壳的瞬间把话摆到眼前”**。这是本项目的代差点。

> 为什么是我们（Superun 第②问的核心）：我们不是从新闻里看到“2000万失语者”才做这个。我们身边就有这样的伙伴——有人不是不想说、是不敢开口；有人一发音就被要求重说，久了干脆沉默；有人思维节奏不同，跟不上对话。这些细节没写进任何需求文档，但我们天天见。而作为做嵌入式端侧的人，我们恰好能把它做成一个离线、低成本、不抢镜头的可穿戴“嘴替”。

## 3. 产品定义

### 3.1 三种交互模式

| 模式 | 触发 | 流程 |
|---|---|---|
| **应答模式**（核心） | IDLE 下 R1 **tap 开始聆听**（push-to-listen） | 听 3~5s → ASR 转写 → 生成 4 候选 → swipe 导航 → tap 确认 → TTS 发声 |
| **主动模式** | IDLE 下 R1 double-tap 唤出 | 常用意图轮盘（吃/喝/如厕/疼痛/呼叫）→ 选择 → 发声 |
| **紧急模式** | 镜腿 double-tap（任意状态） | 跳过确认，立即大声呼救 + HUD 红色闪烁 |

> **为什么用 push-to-listen（按戒指开始听）而非常开：**一举解决三件事——① 明确“说完”的触发时机（免做 VAD）；② 从根上防回声死循环（只在聆听窗口采音）；③ 省 API 调用。代价是多一个动作，对本用户群完全可接受。

### 3.2 输入交互映射（基于 Even R1 SDK 实测能力设计）

> Even R1 戒指与镜腿发**相同事件：tap / double-tap / swipe 上下（无长按）**。事件语义**随状态而变**（IDLE vs 候选态），紧急用镜腿独立表面承载。

| 动作 | 状态 | 功能 |
|---|---|---|
| tap | IDLE | 开始聆听（push-to-listen，听 3~5s） |
| tap | 候选态 | 确认选中 → 发声 |
| swipe 上/下 | 候选态 | 候选高亮 上一个/下一个 |
| double-tap | IDLE | 唤出主动模式轮盘 |
| double-tap | 候选态 | 换一批候选 |
| 镜腿 double-tap | 任意 | 🚨 紧急呼救 |

> **防回声（关键）**：SPEAKING（播 TTS）时静音麦克风，且只在 tap 触发的聆听窗口内采音——从根上杜绝“听到自己刚说的话→又转写→又生成候选”的死循环。

### 3.3 硬件与角色分工

```
👓 Even G2 眼镜   显示+采音：4麦→16kHz PCM · HUD 显示候选（单色绿≤ 4 条）· R1/镜腿事件（插件跑在手机上，眼镜是它的屏幕+输入）
💍 Even R1 戒指   输入：swipe 导航 / tap 确认 / double-tap 换批（镜腿 double-tap 作紧急）
📱 手机           ① Even Hub 插件(TS，实时大脑)：收 PCM/事件 → 调云 API → 推候选回 HUD → 扬声器外放 TTS
                 ② 配置 App：名字/常用语/语气 等个性化 → 写入云端配置
🔊 手机扬声器    TTS 外放（现成，眼镜无扬声器）
☁️ 薄云后端       配置存储 + 云 API 密钥代理（轻量，不做重计算）
☁️ 云 API         ASR + LLM（候选生成）+ TTS
```

> 架构取舍（已定）：用云 API + 手机插件，**笔记本彻底拿掉**——一部手机 + 眼镜 + 戒指搭定。代价：放弃“离线/拔网线”卖点，换成**“随身、即时、个性化”**（云 API 需联网）。好处：把最重、最不确定的 ASR/LLM/TTS 外包给云，2 人 3 天只写“胶水+交互”；且做的是 TS Web 插件，比原生 App 更省事。

## 4. 技术架构

```
 👓 Even G2 眼镜                     📱 手机                          ☁️ 云
 ┌──────────────┐   BLE   ┌──────────────────────┐        ┌──────────┐
 │ 4麦→16kHz PCM│────────→│ Even Hub 插件(TS,实时大脑) │─────→│ ASR 转写   │
 │ HUD 候选(≤4) │←────────│  收PCM/事件→编排→推候选    │←─────│ LLM 出候选 │
 │ R1/镜腿 事件 │────────→│  选中→TTS→手机扬声器外放🔊│─────→│ TTS 合成  │
 └──────────────┘         │ 配置 App: 个性化→写云配置   │        └──────────┘
 💍 Even R1 ─swipe/tap→│                          │──┐   ☁️ 薄后端：配置存储+密钥代理
                          └──────────────────────┘  └─→【读/写配置、代管 API Key】
```

### 4.1 各模块选型

| 模块 | 首选方案 | 降级方案 |
|---|---|---|
| 眼镜端 | Even Hub 插件（TS/Web，evenhub-simulator 无硬件先开发） | 手机屏候选窗（模拟器） |
| 拾音 | Even G2 四麦 → 16kHz PCM（插件接收） | 手机麦 |
| ASR | 云流式 ASR（讯飞/阿里云） | 备用云 ASR |
| 候选生成 | 云 LLM（DeepSeek/通义），prompt 注入个性化配置 | 模板库兜底（预埋场景，保 Demo 命中） |
| TTS | 云 TTS（讯飞/Edge-TTS）→ 手机扬声器 | 预录短语 WAV |
| 输入 | Even R1 事件（swipe/tap/double-tap） | 镜腿触控 |
| 配置 | 手机配置 App → 薄云后端（配置存储） | 插件内置预设（Demo 兜底） |
| 后端/密钥 | 薄云后端代管 API Key + 配置读写 | 密钥暂放客户端（仅本地调试） |

### 4.2 延迟预算（Demo 红线：对方说完 → 候选上屏 ≤ 5 秒）

> 依据：Demo 阶段延迟 ≤5s 可接受，云 API 往返完全够用，选型不再受 1.5s 约束。

| 环节 | 预算 | 依据 |
|---|---|---|
| PCM→插件（BLE） | ~100ms | 眼镜→手机 BLE |
| 云 ASR（流式） | 0.3~1s | 说话中已在转写 |
| 云 LLM 出 4 候选 | 1~2.5s | 短 prompt + 短输出 |
| 推 HUD | ~200ms | 短文本低频刷新 |
| **合计（说完→候选上屏）** | **~2~4s** | Demo 目标 ≤5s 内 ✅ |
| 选中→云 TTS→外放 | +1~2s | 选后追加 |

## 5. 可行性评估（逐环节）

### 5.1 ✅ 已证实（基于 Even Hub 官方文档 + 开发者实测）

| 结论 | 证据 |
|---|---|
| Even G2 App 是 TS 网页插件，**跑在手机上**，有官方模拟器，可零硬件开发 | Even Hub 官方：“Everything runs on the phone; the glasses are the screen” |
| 插件跑在手机 → 可直接联网调云 API，**无需笔记本/单独主机** | 同上；手机即大脑 |
| 四麦输出单流 16kHz PCM，正是 ASR API 所需格式 | Even Hub 硬件规格 |
| 输入事件：press/double-press/swipe 上下（无长按），R1 与镜腿同事件 | Even Hub 硬件规格 |
| 显示 576×288/眼、单色绿 16 级、≤ 4 容器 → 候选只能短文本 | Even Hub 硬件规格；正好对应 4 候选 |
| 眼镜**无扬声器** → TTS 由手机扬声器外放（反而更适合让对方听见） | Even Hub 硬件规格；已定手机播放 |

### 5.2 🟡 待验证（有公开依据，需上手实测——按优先级排序）

| # | 验证项 | 预期依据 | 验证方法 | 失败降级 |
|---|---|---|---|---|
| 1 | **插件能否播音频到手机扬声器**（TTS 代说命脉） | 手机播放现成（用户已确认） | 插件内播一段 WAV 验证扬声器输出 | 降为手机配置 App 播放 |
| 2 | **插件 ↔ 薄后端 ↔ 配置 App 的配置数据通路** | 都在线，过云存储最简 | 配置 App 写一条→插件读到 | 插件内置预设（Demo 兜底） |
| 3 | 端到端延迟 ≤5s（云 ASR+LLM 一轮） | 流式 ASR + 短 prompt | 实测“说完→候选上屏” | 调小 prompt/候选数，或预埋模板库 |
| 4 | Even R1 事件在实机的灵敏度与误触率 | 官方规格支持 press/swipe | 模拟器先验，真机复测 | swipe 改 tap 循环高亮 + tap 确认 |
| 5 | 插件在手机上联网调云 API 的网络/跨域 | Web 插件常规能力 | 插件内 fetch 一个云 API | 经薄后端代理转发 |
| 6 | Even BLE 带宽刷 HUD 的卡顿/断连 | 开发者实测：频繁刷图会断 | 真机测定频刷新上限 | 只刷短文本、降频 |

### 5.3 🔴 高风险项与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 现场网络不稳/断网，云 API 调不通 | 中高 | 候选出不来 | ① 备 4G 热点；② **模板库本地兜底**（预埋 Demo 对话必命中，无网也能演）；③ 预录关键句 TTS |
| 现场嗧杂，ASR 识别错乱 | 中高 | 候选全错 | ① 依赖眼镜四麦阵列指向佩戴者前方；② Demo 对话预埋脚本，模板库保证 100% 命中；③ HUD 显示 ASR 原文，错了也能圆场 |
| Even BLE 带宽窄/现场 2.4G 干扰导致卡顿断连 | 中 | HUD 刷不动/断连 | ① 只刷短文本、低频更新；② 重连守护；③ 备用输入：镜腿触控（与 R1 同事件） |
| Even R1/眼镜 硬件故障/没电 | 低 | 致命 | 充电检查列入演前 checklist；镜腿触控备用输入 |
| swipe/tap 在嗧杂交互中误触 | 中 | 选错候选 | 确认一步才发声（tap 选中→再 tap 确认）；紧急键放镜腿独立表面 |
| 两人 3 天工期爆炸 | 中 | 砍功能 | 功能砍序（见 §7 的 P0/P1/P2） |

### 5.4 综合结论

**可行。** 核心链路（眼镜麦→手机插件→云 ASR→云 LLM 出候选→HUD→R1 选中→云 TTS→手机扬声器）每一环都有官方依据或成熟服务支撑。把 ASR/LLM/TTS 外包给云 API 后，我们只写“插件交互 + 云编排 + 薄后端”，2 人 3 天完全可达。最大不确定项是 **插件能否播音到手机扬声器**（TTS 代说命脉）和 **现场网络**——前者有配置 App 播放兜底，后者有模板库本地兜底，均非致命。

> 叙事口径：因走云 API，不再强调“离线/拔网线”，改打**“随身、即时、个性化”**：一副眼镜+一枚戒指+手机，随时随地帮你把话说出口；配置 App 让它越用越懂你。

## 6. Demo 剧本（4 分钟）

1. **【冷开场】** 队员 B 上台全程不发一言（戴着 Even G2）。A：“接下来 2 分钟，他一句话都不会说，但他会回答你们任何问题。”
2. **【应答演示】** A/评委提问：“你叫什么名字？”“项目做完了吗？”“累不累？”——候选浮现在 B 眼前 HUD，B 只在 R1 戒指上 swipe 选中、tap 确认，音箱代答（预埋对话脚本，候选必命中）
3. **【紧急模式】** A：“如果他突然不舒服呢？”——B 敲镜腿两下（double-tap），设备大声呼救、HUD 爆红
4. **【个性化】** “而且每个人的候选都不一样——这是他在手机 App 里配的常用语和语气。他越用，它越像他自己在说话。”
5. **【收尾】** “不是每个人都能从容地开口——有人社恐、有人发音被误解、有人思维节奏不同。他们不是没有话说，只是卡在了‘说出口’那一步。我们想让表达，对每个人都再容易一点。”

**演前 checklist**：R1 戒指与眼镜电量 >50%／眼镜+戒指已与手机配对／云 API key 有效 + 4G 热点就绪／个性化配置已设好／模板库兜底已开（无网也能演）／备用 Demo 视频在手机里。

意图分类（关键词匹配，优先级从上到下）：
