# 无声之声 · Demo 联调与 G2/R1 Bench 指南

> 目标：在固定手机热点内，把 Even G2、R1、手机插件和 Mac backend
> 接成可重复验证的演示闭环。浏览器或 simulator 通过不能替代真机结论。

## 1. 当前真实拓扑

```text
G2 四麦 PCM ─BLE→ 手机 Even Hub 插件 ─LAN→ Mac backend /asr
                                               ↓
手机扬声器 ← /tts ← 用户确认 ← R1 ← G2 HUD ← /candidates
```

当前 backend 的 SenseVoice ASR 跑在 Mac，因此 Mac 仍在 Demo 链路里。手机中的
`localhost` 指手机自己，真机包必须使用 Mac 在热点中的局域网地址。

正常链路的候选来自 LLM；LLM 失败但 backend 可达时走 backend 模板；ASR 成功而
`/candidates` 不可达时走客户端语义模板；ASR/backend 整体不可达时只进入
“快捷表达”，不声称理解了对话。

## 2. 固定热点与 backend

1. 手机开启固定热点，Mac 连入该热点；G2/R1 通过 Even App 与同一手机连接。
2. 在 Mac 查询当前地址：

```bash
ipconfig getifaddr en0
```

3. 启动 backend：

```bash
test -f backend/.env || cp backend/env.example backend/.env
npm run dev:backend
```

4. 在 Mac 和手机浏览器分别打开：

```text
http://<Mac-IP>:8787/health
```

期望：

```json
{ "ok": true, "llm": true, "tts": true, "asr": true, "uptime": 10 }
```

`asr=false` 表示模型未安装，不能继续真机语音验收。`llm=false` 时仍可模板演示，
但不能宣称本轮候选由 LLM 生成。backend 无鉴权且允许跨域，只能放在可信热点，
不要映射到公网。

## 3. 浏览器开发与自动化检查

```bash
npm install
npm test
npm run typecheck
npm run dev:backend
npm run dev:glasses
```

浏览器键盘映射：

- Enter：tap
- ↑ / ↓：候选导航
- Space：double-tap
- Esc：镜腿紧急手势

手机页“设备检查”卡显示运行环境、backend 能力、PCM 字节率、各阶段耗时、候选
来源、发声路径和最近错误。诊断区不会展示 profile、原始音频或密钥。

隐私快捷模式的验收标准是：轻点后不采音、不产生 backend 请求，候选立即来自
本地常用语/场景短语，发声只走 Web Speech。

## 4. 一键预检与打包

真机包不要手改 `app.json` 中的 IP。运行：

```bash
npm run demo:pack -- --backend-url http://<Mac-IP>:8787
```

该命令会依次：

1. 拒绝 `localhost`；
2. 检查 `/health` 的 ASR/LLM；
3. 调用 `/candidates` 并验证 `source=llm`、恰好四条、去重、≤12 字；
4. 调用 `/tts` 并确认返回非空音频；
5. 用同一 URL 注入 `VITE_BACKEND_URL`；
6. 在 `glasses-app/.demo/app.json` 生成仅包含该 origin 的网络白名单；
7. 输出 `glasses-app/voiceless.ehpk`。

明确接受模板候选时才使用：

```bash
npm run demo:pack -- --backend-url http://<Mac-IP>:8787 --allow-template
```

开发地址 QR：

```bash
npm --workspace glasses-app run dev
npm --workspace glasses-app run qr -- --ip <Mac-IP>
```

## 6. 分层测试

### A. 启动、HUD 与重连

1. 加载本轮 `.ehpk`，确认手机设备检查卡显示 `Even bridge`。
2. G2 应显示待机首屏。
3. 断开再重连 G2，确认诊断状态变化且 HUD 恢复。
4. 重载插件、重启 backend、锁屏再恢复，各执行一次。

失败排查：

- bridge 一直未知：检查 Even App 插件是否为本轮包。
- 手机能访问 `/health` 但插件不可达：核对 `.demo/app.json` 白名单和构建时 URL。
- HUD 不恢复：记录 Even App/G2 固件版本和重连事件。

### B. PCM 与 ASR

分别录制 1、3、5 秒正常中文，并记录：

| 时长 | PCM 字节 | 字节/秒 | ASR 文本 | ASR 耗时 |
|---|---:|---:|---|---:|
| 1 秒 | | | | |
| 3 秒 | | | | |
| 5 秒 | | | | |

期望 PCM s16le / 16kHz / mono 约为 `32000 bytes/s`，允许 ±10%。数字静音应
识别为空；正常中文应得到非空文本。若偏差明显，先保存字节数和固件版本，不要
直接修改 SenseVoice 采样率。

### C. R1 与镜腿输入

逐项执行并记录一次物理动作是否产生一次业务动作：

| 动作 | 期望 | 结果 |
|---|---|---|
| IDLE tap | 进入 LISTENING | |
| LISTENING tap | 提前结束采音 | |
| swipe up/down | 高亮循环移动且方向正确 | |
| 候选 tap ×2 | 锁定后发声 | |
| R1 double-tap | 换一批/换主动分组 | |
| 左镜腿 double-tap | 紧急抢占 | |
| 右镜腿 double-tap | 紧急抢占 | |

若方向或来源不符，只调整事件映射并记录 Even App/G2/R1 固件版本。

### D. 五轮正常闭环

连续执行五轮并填写：

| 轮次 | 听到→候选 | 候选数/最长字数 | 候选来源 | 确认→出声 | 播放结果 |
|---|---:|---|---|---:|---|
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |
| 4 | | | | | |
| 5 | | | | | |

每轮必须满足：

- 停止采音到候选上屏 ≤5 秒；
- 恰好四条、当前批次不重复、每条 ≤12 字；
- 确认到开始发声目标 ≤2 秒；
- 音频结束前保持 SPEAKING；
- SPEAKING 期间 tap 不会重新开麦；
- MP3 不可用时设备检查卡明确显示本机语音或未发声。

### E. 紧急抢占

分别从 LISTENING、THINKING、CANDIDATES、SPEAKING 触发镜腿双击：

1. 旧采音、请求和声音停止；
2. 紧急 HUD/手机红色页出现；
3. 两遍紧急语依次播放，不重叠；
4. 点手机解除后立即停声并回 IDLE；
5. 等待 12 秒，旧结果不得重新覆盖 HUD。

### F. 故障与边界

- LLM 禁用：backend 返回 `source=template`，仍为四候选。
- backend 断开：最多在请求超时后进入“后端不可达 · 快捷表达”，不卡死。
- TTS 失败：降级 Web Speech；两者都失败时不显示“已替你说”。
- BLE 断开：手机提示断开，重连后恢复 HUD。
- 隐私快捷：backend 日志无新请求、无 PCM、候选即时出现。
- 主动分组测试 0/1/3/4/10 条和超长短语；保存时空分组/超长短语必须被阻止，
  运行时仍不得出现空候选。

## 7. 交付判定

汇报时分别写明：

- 自动化测试是否通过；
- TypeScript 与生产构建是否通过；
- `demo:pack` 是否通过、使用的 backend URL 和是否带 `--allow-template`；
- 浏览器/simulator 结果；
- G2 真机结果；
- R1 真机结果；
- 未通过项的实际观测值和下一步。

不得把“编译成功”“浏览器通过”写成“已在 G2/R1 验证”。
