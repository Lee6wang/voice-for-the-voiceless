# 无声之声联调指南

> 更新：2026-07-24
> 分支：`feat/b-profile-flow`
> 目标：把 Even Hub 插件、Mac backend、Even G2 和 Even R1 按同一套步骤接通。

## 1. 当前可联调到什么程度

代码侧已经具备完整最小链路：

```text
G2 PCM → /asr → /candidates → G2 HUD 四候选
                                  ↓ R1 选择
手机扬声器 ← /tts ← 用户确认的候选
```

同时已经实现：

- 手机控制页配置 backend、profile、场景和音色；
- `IDLE → LISTENING → THINKING → CANDIDATES → SPEAKING` 状态机；
- R1/镜腿事件映射、HUD 高亮、换一批；
- backend 断开时插件本地模板兜底；
- MP3 → Web Speech → HUD 文字三级发声降级；
- 镜腿紧急手势抢占采音、网络请求和普通播报；
- 时间上下文默认开启，GPS 默认关闭并由用户主动授权；
- 插件可构建并打包为 `voiceless.ehpk`。

2026-07-24 已在浏览器跑通候选生成、高亮、换一批、离线模板和紧急抢占，
并确认页面无控制台错误。

目前还不能写成“已完成”的部分：

- G2 真机 PCM 格式和中文识别准确率；
- R1 真机事件源与上滑/下滑方向；
- Even App WebView 在手机上的 MP3 自动播放；
- 真机端到端延迟。

这四项必须由拿到设备的成员按本文第 6 节实测并记录，不能只凭 simulator
结果勾选。

## 2. 联调拓扑和地址

开发时手机、G2/R1 和 Mac 应在同一 Wi-Fi 或手机热点。backend 监听：

```text
0.0.0.0:8787
```

Mac 当前可见的局域网地址是：

```text
10.80.13.105
```

因此本轮真机填写：

```text
http://10.80.13.105:8787
```

注意：

- 手机中的 `localhost` 指手机自己，不是 Mac；
- 换 Wi-Fi 后先用 `ipconfig getifaddr en0` 或 `ifconfig | rg "inet "` 重查；
- 新 IP 必须同时加入 `even-hub-plugin/app.json` 的 network whitelist，然后重新
  构建/打包；
- macOS 防火墙弹窗出现时允许 Node 接收入站连接；
- backend 没有鉴权，只能用于可信局域网，不要把 8787 端口直接暴露到公网。

## 3. 启动 backend

在仓库根目录：

```bash
npm install
test -f backend/.env || cp backend/env.example backend/.env
npm run dev:backend
```

如果 `backend/.env` 已存在，不要覆盖。真实 LLM 需要其中配置兼容 OpenAI 的
provider；ASR 模型安装见 `backend/models/README.md`。

先在 Mac 验证：

```bash
curl http://127.0.0.1:8787/health
curl http://10.80.13.105:8787/health
```

预期形状：

```json
{ "ok": true, "llm": true, "tts": true, "asr": true, "uptime": 10 }
```

含义：

- `llm=false`：候选仍可用，但会走模板；
- `asr=false`：模型没装，真实语音链路无法继续；
- `tts=true` 只表示服务已启用，首次合成仍依赖网络，已缓存句子可离线返回。

## 4. 无硬件的接口与页面联调

启动插件开发页：

```bash
npm run dev:plugin -- --host 0.0.0.0
```

浏览器打开终端显示的地址。在“连接”中填 backend URL，然后：

1. 确认 backend/LLM/TTS/ASR 状态灯；
2. 点一次“启用声音”；
3. 保存名字、常用语、语气、紧急表达；
4. 点“模拟对方说话”；
5. 用上滑/下滑、按一下、双击按钮走完整状态机；
6. 断开 backend，再次模拟，确认出现“候选（离线模板）”且仍有 4 条。

单独验证候选接口：

```bash
curl -s http://127.0.0.1:8787/candidates \
  -H 'Content-Type: application/json' \
  -d '{
    "turnId":"joint-001",
    "heardText":"你中午想吃什么？",
    "profile":{
      "userId":"demo",
      "name":"小明",
      "tone":"gentle",
      "commonPhrases":["容我想想"]
    },
    "exclude":[],
    "context":{
      "localTime":"12:30",
      "timeOfDay":"午餐时段",
      "scene":"餐厅"
    }
  }'
```

验收：恰好 4 条、无重复、单条不超过 12 个字符；是否走 LLM 以 `/health.llm`
和 backend 日志为准。

## 5. simulator 与打包

先保持 Vite 正在运行，再开另一个终端：

```bash
npm --workspace even-hub-plugin run simulate
```

正式打包检查：

```bash
npm --workspace even-hub-plugin run pack
```

成功后产物在：

```text
even-hub-plugin/voiceless.ehpk
```

该文件被 `.gitignore` 忽略，不上传 Git。使用 Even App 的开发者模式加载开发
地址时，可按当前 CLI 生成局域网 QR：

```bash
npx evenhub qr --ip 10.80.13.105 --port 5173
```

若手机无法打开 QR 地址，优先检查同网段、Vite 是否使用 `--host 0.0.0.0`，
再检查防火墙。

## 6. G2 + R1 真机联调顺序

不要一次排查整条链路，按以下顺序逐层确认：

### A. 桥和 HUD

1. 官方 Even App 已连接 G2/R1；
2. 插件控制页“眼镜”状态灯变绿；
3. G2 显示“无声之声已就绪”。

### B. 输入

在 `IDLE` 按一下 R1，应进入 `LISTENING`；再按一下，应进入 `THINKING`。
出现候选后：

- 上滑/下滑：高亮循环移动；
- 按一下：确认并发声；
- 双击 R1：换一批；
- 双击镜腿：无论当前状态都抢占并播紧急表达。

若方向相反或双击来源判断错误，只修改
`even-hub-plugin/src/main.ts` 的 `mapInput()`，并在提交信息中写明实测固件版本。

### C. 采音和 ASR

让对方连续说 1～3 秒。backend 应收到 `/asr`，手机镜像区应出现识别原文。
当前协议固定为：

```text
PCM s16le / 16 kHz / mono / 无 WAV 头
```

若全是空文本，先记录真实 PCM 长度与 1 秒字节数。目标约为 `32000 bytes/s`；
不要在未确认格式前调整模型。backend 已包含保守静音门：全数字静音应返回
空文本，而不是 SenseVoice 偶发的短英文幻觉。

### D. 发声

先在手机页主动点一次“启用声音”，再由 R1 确认候选。预期优先播放 backend
返回的 MP3。若失败，插件依次降级到 Web Speech 和 HUD 大字。

### E. 紧急抢占

分别在 `LISTENING`、`THINKING`、`CANDIDATES`、`SPEAKING` 时双击镜腿。
每次都应停止旧流程，且旧 ASR/LLM 结果不能在稍后重新覆盖 HUD。
